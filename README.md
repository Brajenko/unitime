# Модуль занятости

Веб-приложение: регистрация по email и паролю, команды со ссылкой-приглашением, подключение календарей (Google / Яндекс / Apple или публичная ссылка на .ics), сетка занятости команды. Зелёным подсвечено всё время, куда встанет встреча выбранной длины; при наведении слот достраивается от клетки. Названия событий в базу не пишутся.

## Запуск

```bash
cp .env.example .env
echo "APP_SECRET=$(openssl rand -hex 32)" >> .env
docker compose up --build
```

`APP_SECRET` обязателен (не короче 32 символов): без него API и воркер не стартуют. Из него выводится ключ шифрования токенов календарей.

Откройте [http://localhost:3000](http://localhost:3000).

Одна команда поднимает Postgres, Redis, API, воркер, планировщик (`beat`, опрос календарей раз в 15 минут) и веб.

## OAuth-приложения (Google и Яндекс)

Это не хостинг. Нужны только клиентский id и секрет, как у любого «Войти через …».

### Google

1. Создайте проект в [Google Cloud Console](https://console.cloud.google.com/).
2. Включите **Google Calendar API**.
3. OAuth consent screen: External, статус Testing, добавьте тестовые email.
4. Credentials → OAuth client ID → Web application.
5. Authorized redirect URI: `http://localhost:3000/api/auth/google/callback`
6. Пропишите в `.env`:

```
GOOGLE_CLIENT_ID=...
GOOGLE_CLIENT_SECRET=...
GOOGLE_REDIRECT_URI=http://localhost:3000/api/auth/google/callback
```

Запрашиваются `calendar.calendarlist.readonly` и `calendar.freebusy`: список календарей и занятость без названий.

### Яндекс

1. Зарегистрируйте приложение на [oauth.yandex.ru](https://oauth.yandex.ru/).
2. Тип: для авторизации пользователей, платформа Web.
3. Redirect URI: `http://localhost:3000/api/auth/yandex/callback`
4. Права: `calendar:all` и `login:email`.
5. В `.env`:

```
YANDEX_CLIENT_ID=...
YANDEX_CLIENT_SECRET=...
YANDEX_REDIRECT_URI=http://localhost:3000/api/auth/yandex/callback
```

После входа сервис ходит в CalDAV `https://caldav.yandex.ru` с заголовком `Authorization: OAuth …`.

### Apple

OAuth для iCloud Calendar нет. На шаге подключения:

1. Включите двухфакторную аутентификацию Apple ID.
2. [account.apple.com](https://account.apple.com) → Sign-In and Security → App-Specific Passwords.
3. Вставьте email и пароль приложения в форму.

Обычный пароль Apple ID сервер отклонит.

## Как пользоваться

0. Зарегистрируйтесь, создайте команду (список команд в шапке → «+ Новая команда…») и отправьте участникам ссылку кнопкой **Пригласить** в блоке «Команда».
1. В блоке «Моя занятость» нажмите **+ Календарь**.
2. Выберите плитку, войдите в аккаунт (для Apple — пароль приложения).
3. Отметьте календари галочками → **Подключить**.
4. На сетке появятся градации «сколько календарей свободны» и синяя рамка предложенного слота.

Кнопка **⟳ Обновить** над сеткой ставит ту же задачу воркеру. Стрелки ← → листают недели, длительность встречи выбирается рядом, а детализация, точные даты и часы спрятаны в **⚙ Вид**.

## Фиксация встречи

Выберите команду и нажмите на зелёную клетку: слот выделится рамкой, а под сеткой появится карточка «Выбран слот» с числом свободных, необязательным названием и кнопкой **Зафиксировать встречу**. Зафиксированная встреча подсвечивается синим на сетке у всей команды и попадает в блок «Встречи» в боковой панели. Фиксировать может любой участник команды, отменить — автор встречи или владелец команды.

Две встречи одной команды не могут пересекаться: это гарантирует ограничение исключения в Postgres (`EXCLUDE USING gist (team_id WITH =, period WITH &&)`), поэтому при одновременной фиксации одного времени проходит только одна, вторая получает 409.

API: `POST /api/teams/{id}/meetings` (`start`, `end`, `title`), `GET /api/teams/{id}/meetings`, `DELETE /api/meetings/{id}`.

## Ручные окна (без календаря)

Если календаря нет, нажмите в блоке «Моя занятость» **✎ Окна вручную**. Сетка переключится на вашу неделю без занятости команды; отметьте клетки, когда вы свободны: кликом или выделением прямоугольника мышью. Если при выделении потянуть обратно, лишние клетки возвращаются как были. Затем нажмите **Сохранить**. В днях, где отмечено хотя бы одно окно, остальное время считается занятым. Дни без отметок команда не учитывает: в них участник как будто не подключился, поэтому разметка одной недели не гасит слоты в другие недели. Участник с ручными окнами учитывается в сетке команды наравне с остальными и показан капитану как «отметил окна вручную».

Календарь главнее: если подключён хотя бы один календарь, сетка считается по нему, а ручные окна не учитываются.

API: `GET/PUT /api/me/availability?date_from&date_to&tz`. PUT заменяет окна за указанные дни, пустой список их очищает.

## Кто подключился

Над списком участников показано «Учтено в сетке: N из M». Участники без календарей, с потерянным доступом (`auth_failed`) или с устаревшими данными (старше 30 минут) показаны первыми, а над сеткой появляется предупреждение, что зелёные окна могут быть неверными. Статус участника приходит в `members[].status`: `ok`, `no_calendars`, `auth_failed`, `stale`.

Сетка рисуется в часовом поясе браузера (параметр `tz` у `/api/grid`) и открывается мгновенно из локального кеша с подписью «Данные от ЧЧ:ММ», пока идёт обновление.

## Публичная ссылка на календарь

Плитка «Ссылка на календарь» принимает публичный `.ics` (`https://` или `webcal://`) без входа в аккаунт. Это запасной путь: файл скачивается целиком, календари не выбираются. Сервер не ходит на внутренние адреса (защита от SSRF), URL хранится зашифрованно.

## Проверки без браузера

```bash
cd backend
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
pytest
```

Сквозной тест API на реальном Postgres (Redis подменяется fakeredis). Внимание: тест очищает таблицы (`TRUNCATE`), указывайте отдельную тестовую базу, а не ту, где лежат ваши данные:

```bash
RUN_INTEGRATION=1 DATABASE_URL=postgresql+psycopg://slot:slot@localhost:5432/slot pytest tests/test_api_integration.py
```

Фронтенд: `cd frontend && npm test` (vitest, чистые функции) и `npm run build` (проверка типов и сборка).

Property-тест алгоритма слотов (10 000 случайных расписаний против поминутного эталона) входит в обычный `pytest`.

Проверка приватности: после привязки календаря в дампе не должно быть ни паролей, ни названий событий.

```bash
docker compose exec postgres pg_dump -U slot slot | grep -iE "<пароль приложения>|<название события>"
```

Нагрузка на `/api/grid`: `loadtest/grid.js` (k6), три прогона — без кеша (`GRID_CACHE_ENABLED=false`), с кешем, с ETag.

## Стек

FastAPI, Celery, Redis, PostgreSQL (`tstzrange`), React + Vite. Секреты шифруются AES-GCM, ключ выводится из `APP_SECRET` через HKDF. Синк раз в 15 минут разносится по времени (не пачкой), задача синка ограничена 60 секундами.
